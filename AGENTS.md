# AGENTS.md

Guidance for every agent and teammate working in this repo.

## Source of truth

`SPEC.md` defines what the project does. Read the sections your task touches before writing code. If the spec is wrong or silent on something that matters, raise it with Owen. Don't improvise behaviour the spec doesn't describe.

## Conventions

- Write only the current state. No backwards-compatibility shims, versioned comments or dead code.
- Comments say *why* the code can't show, in one line.
- Parse external data (HTTP bodies, model output, files) with the pydantic models in `isaacs_mom/contracts.py` at the boundary, then trust the types inside.
- Domain logic lives in plain, tested modules; servers, the CLI and the dashboard are thin adapters.
- Risky logic ships with a behaviour test. SPEC §2's rules each have one.
- Done means `scripts/verify.sh` prints READY and the real thing was exercised.
- Priority: quality first.
- Stay inside your workstream's folder (SPEC §5). A change to `contracts.py` updates every caller in the same PR and is called out in the PR body.
- Stop a server you started by its port (`lsof -ti tcp:<port> -sTCP:LISTEN | xargs kill`), never by name.
- Never commit secrets (`.env`), `runs/`, model weights, or personal content.
- Commits have no co-author or "generated by" lines.

## Workflow

- Branch from `phase-1`, one branch per piece of work, and open a PR into `phase-1`. Never push to `phase-1` or `main` directly.
- A PR merges only through `node scripts/merge-gate.mjs <pr> owenbonc/isaac-s-mom`: CI green and the PR body's `## Review` section filled (`- deslop:`, `- no-comments:`, `- ponytail-review:`).
- Agents in a worktree run `scripts/agent-setup.sh origin/phase-1` first.

## Skills

| Skill | Used for |

| pstack principles | Model the domain, boundary discipline, type-system discipline, test behaviour, prove it works. |

## Layout

See SPEC §5. Workstreams: 1 `isaacs_mom/sim/mujoco/`, 2 `isaacs_mom/teacher/`, 3 `isaacs_mom/validator/`, 4 `isaacs_mom/student/`, 5 `isaacs_mom/orchestrator/` and `docs/`. Foundation (Owen): `contracts.py`, `sim/base.py`, `sim/fake.py`, `configs/`, `scripts/`, CI.

## Commands

```
uv sync                         # install
uv run mom run --sim fake       # the teach -> fine-tune loop (SPEC §3.6) on FakeSim
uv run pytest                   # tests
scripts/verify.sh               # the definition of done; `secrets` runs only the history scan
```
